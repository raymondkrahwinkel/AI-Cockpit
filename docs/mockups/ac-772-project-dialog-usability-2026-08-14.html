AC-772 — Nieuw/bewerk project: usability-voorstellen

Vervolg op de vraag die Raymond stelde nadat het create/edit-scherm (sectie 8 van de vorige mockup) letterlijk was nagetekend: is dát scherm zelf wel prettig voor iemand die geen developer is? Twee voorstellen hieronder — complementair, geen of/of: P1 herschikt het bestaande scherm, P2 zet er een lichter instapscherm voor. Beide zijn los te nemen.

HTML-proxy van een Avalonia-scherm <details> is een native HTML-element — het klapt hieronder écht open/dicht, geen JavaScript. In Avalonia wordt dat een Expander.

Let op — scope. De ticketbeschrijving van AC-772 sluit structurele wijzigingen aan dit scherm op dit moment nog expliciet uit ("alleen taal" staat er). Dit hier is dus een voorstel dat verder gaat dan de huidige v1-afbakening. Onderaan een aanbeveling voor hoe dat op te knippen.

ProbleemGevolg voor iemand die geen developer is
Alle zes secties staan altijd open, ook MCP overlay, Isolate in git worktree en de resource-rollen-combo.Een project zonder code (bv. "Facturen") toont evenveel technische knoppen als een softwareproject. Niets is verplicht, maar alles is zichtbaar.
Het scherm toont pas een resultaat als je het al gesloten hebt.Je vult "Facturen" in en moet je voorstellen hoe die kaart er straks uitziet.
900×760, één lange scroll, geen ingang voor "ik wil gewoon snel starten".Iemand die alleen een naam en een map wil instellen doorloopt hetzelfde scherm als iemand die een MCP-overlay configureert.

1Voorstel P1 — Basics altijd zichtbaar, de rest achter één Advanced-vouw

Zelfde zes secties, andere volgorde van zichtbaarheid: Basics (Name, Logo, Category, Description, Folder, Profile) blijft altijd open — dat is wat elk project nodig heeft. Alles wat er in de praktijk zelden aangeraakt wordt (Behaviour, Where it is tracked, Memory/instructions/reference voorbij de eerste Memory-rij, worktree-isolatie, MCP overlay) valt onder één <details>-vouw, dicht bij openen. Erbij: een live-preview van de kaart naast het formulier, zodat "Facturen" meteen zichtbaar wordt als de kaart die een collega straks ziet.

3Taal die deze twee voorstellen nog niet oplossen

Los van indeling: een paar labels in "Advanced" zijn nog steeds jargon zodra iemand er wél in kijkt. Zelfde soort tabel als bij de Projects-pagina, nu voor dit scherm.

MCP overlayWat is MCP?"Tools this project's sessions can use" — met dezelfde checklist eronder.
Isolate new sessions in a git worktreeWat is een worktree?De bestaande hint ("every session starts in its own worktree") is al goed; label zelf iets korter: "Give every session its own copy of the code".
Resource-rol Memory / Instructions / ReferenceWat is het verschil?Eén regel voorbeeld per keuze in de dropdown zelf (bv. "Instructions — a style guide or README to follow").

4Aanbeveling

Beide, en beide zijn klein genoeg om los te leveren. P1 (Basics/Advanced + preview) is de goedkoopste winst: geen nieuw scherm, alleen een Expander om vier secties heen en een preview-paneel dat het bestaande kaart-uiterlijk hergebruikt. P2 (quick-add) is een nieuw, klein venster maar hooguit 60 regels AXAML — het roept gewoon het bestaande ProjectDialogViewModel aan met minder velden zichtbaar, geen nieuwe save-logica.

Scope-voorstel: dit hoort niet in AC-772's v1 (die sluit structurele wijzigingen aan dit scherm nu juist uit). Twee opties: (a) een vervolgticket "Nieuw/bewerk project — usability voor niet-developers", met deze mockup als basis, of (b) de scope-afbakening van AC-772 nog één keer oprekken, zoals dat nu al twee keer eerder gebeurd is in dit ticket. Mijn voorkeur is (a) — AC-772 is al drie mockup-rondes verder dan de oorspronkelijke titel ("toolbar + Projects-redesign") dekt, en dit is een goed afgebakend, zelfstandig stuk werk.

# AC-1722 Uren Dag Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Productivity Uren workspace with manual duration entry, one persistent stopwatch, Day navigation and editing, a shared sidebar controller, and today's textual badge.

**Architecture:** A backend plugin is the only caller of `ICockpitTimeEntries` and exposes typed operations over the plugin channel. A separate code-built Avalonia UI assembly owns one shared controller used by the workspace, Tijd sidebar, and Uren badge.

**Tech Stack:** .NET 10, C#, Avalonia 12, Cockpit plugin SDK 3.18, xUnit, headless Avalonia view journeys.

**Spec:** `docs/superpowers/specs/2026-10-25-ac-1722-uren-dag-design.md`

## Global Constraints

- Plugin manifest: `abstractionsVersion: 3`, `minHostVersion: 0.108.0` because its menu uses the 3.19 icon/tone additions.
- The plugin stores no time data; every read and mutation goes through host `ICockpitTimeEntries` in the backend.
- UI and backend communicate only through typed channel contracts compiled into both assemblies.
- Use code-built Avalonia and existing theme resources; no new dependency.
- Week is visible but disabled with “komt”; measured time, proposals, context column, and overview stay out of M1.
- The only project fallback is the final segment of `ActiveSessionWorkingDirectory`; AC-1737 owns the real host project API.
- New plugin test project stays below ten cases; ViewTests remains at its current ceiling.

## Review Focus

- Local-midnight and DST boundaries: a selected day must map to a half-open range with the correct local offsets.
- Repeated clicks and overlapping refreshes: the controller must serialize mutations and never re-enable a second stopwatch start.
- Stale or unavailable backend: views must show an error without losing the last successful snapshot.
- Empty/whitespace description and invalid/non-positive duration: no host mutation occurs and the form explains the problem.
- Offered/booked entries: no edit or delete action is rendered even after navigation or refresh.

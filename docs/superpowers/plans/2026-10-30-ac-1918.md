## Implementation decisions

- Migration uses the shared pairing secret, or the active controller's authenticated key prefix; a friendly key label is not an identity.
- The composition root identifies desktop versus server from the frontend registration.
- Third-member connections authenticate both TLS public keys against a signed membership log extending the existing local log. This is the minimum log exchange needed for mutual credentials; ongoing propagation belongs to AC-1919.
- An offline existing member does not undo the new join. Its connection attempt has a five-second timeout and logs a warning; heartbeat/reconnection belongs to AC-1919.
- Old pairing settings remain intact; both machines receive the migration notification.

# Wispslate icons

Blue is Cockpit, teal is Depot. Everything in this folder is generated by
[`scripts/generate-brand-icons.sh`](../scripts/generate-brand-icons.sh) — edit the script, not the output.

Its one input is `src/Cockpit.App/Assets/BrandMark.png`, the render the app already carries: the title bar
and the About dialog draw it, and `scripts/generate-appicon.py` builds the window icon from it. Reading it
there means the repository holds the mark once instead of keeping a second copy under `brand/`.

| File | What it is |
|---|---|
| `wispslate-mark-<colour>.png` | The whole mark — streaks, W, plate — centred in a 512² square |
| `wispslate-icon-<colour>.png` | The icon: the W on its plate, framed to fill the square, 1024² |
| `icons/<colour>/<size>.png` | The icon at 16, 24, 32, 48, 64, 128, 256 and 512 |
| `icons/wispslate-<colour>.ico` | The same sizes up to 256, PNG-compressed, for Windows and as a favicon |

## Why there is one render and two colours

The sheet these came off held two icons, one per product, and they were separate renders: 276×206 against
205×133, a W drawn at different proportions in each, and a plate of a different shape under it. Side by
side they read as two pictures rather than one mark in two colours. Neither was square either, so every
square target — taskbar, dock, favicon — had to stretch the mark or letterbox it.

So one render carries the geometry and the other colour is derived from it by mapping luminance onto a
ramp taken from the teal render's own palette. The alpha channels of the two files are byte-identical:
lay them over one another and only the colour differs, which is the property the whole set is for. Blue
is the master because the teal render is clipped along its top edge — its solid pixels sit on row 1 of
its canvas — and is the smaller of the two.

## Why the icon is framed closer than the mark

The mark is 1.66:1. In a square frame that can only ever be a wide band with empty space above and below
it, and at 32px and under the band collapses into a smudge — a W with motion streaks behind it is a lot
of detail for 32 pixels. The icon composition frames the same artwork closer: the W and its plate fill
the square, and the streaks run off the left edge instead of shrinking to fit. That draws the mark 1.3×
taller in the same number of pixels (it spans 0.695 of the icon's height against 0.531 of the mark's),
and it is one drawing at every size rather than a set that changes picture halfway up the ladder.

## Where it stops: 16px

At 32px the W reads cleanly. At 16px it is legible but marginal — you can count the strokes, and the
blue's magenta interior fights the letterform while the teal reads closer to a texture than a letter.

Framing it closer still does not fix that, and neither does sharpening after the downscale, which only
adds ringing that then becomes the most visible thing in the icon. The reason is the artwork: this is a
glossy 3D render with a glow and no flat silhouette, and 16 pixels cannot hold a highlight, a shadow and
a stroke edge at once. A crisp 16px entry wants a drawn silhouette of the W — a second piece of brand
artwork, not a crop of this one.

## Its limit: resolution

The mark inside the source render is 244px wide. Every size above roughly 512 is interpolation, so a
1024 icon is soft where it should be crisp — visible on a Retina Mac, where the Dock draws the 512 entry
at 1024 real pixels. The canvas is 1024 anyway because that is what a macOS `.icns` is built from, and
this set has to be able to supply one. A crisper large icon needs the mark re-rendered larger at source;
nothing that can be done downstream of this file recovers detail that was never in it.

## What this set does not do yet

The cockpit's own icon does not come from here. `scripts/generate-appicon.py` reads the same
`BrandMark.png` and draws it on a dark tile, scaled by width — so it carries the two artefacts this set
removes, and at 16px the mark inside the tile is smaller still than the ones here. Pointing that script
at `icons/blue/` would fix both. It is not this change: it would replace an icon that shipped one commit
ago, it needs Pillow to rebuild what that script writes, and whether the icon stays a tile or becomes
the bare mark is a decision, not a cleanup.

Nothing else reads this folder yet either — no packaging step, no workflow. That is the state it is
meant to be in: the set exists and is pinned by a test, and wiring it up is the next step, not this one.

## Regenerating

```
scripts/generate-brand-icons.sh
```

Needs ImageMagick 7. Output is deterministic — a run that changes nothing rewrites the same bytes — so a
diff here means something actually changed.
